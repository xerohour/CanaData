
## 2026-05-04 - Optimize `CanaParse` filtering logic
**Learning:** In `CanaParse.py`, during the filtering step (`apply_filters` and `is_match`), joining row values into `row_str` dynamically inside the inner loop over all rows *for every single filter* incurs an extreme performance hit (O(N*M) where N is the number of filters and M is the number of rows). Further, `is_match` mutates the input data by appending `thc+` and `cbd+` fields which introduces memory leaks and breaks subsequent processing due to dirty data copying on repeated filtering. It also causes performance regressions.
**Action:** Pre-calculate representations of data rows (`row_str`) statically before looping over filters. Precompile regular expressions as class-level constants (e.g. `_thc_pattern`) rather than interpolating strings inside deeply nested loops. Do not mutate source variables or iterables in pure evaluation functions (like `is_match`); instead defer the derivation of data (like pulling THC and CBD out of descriptions) strictly to the view/rendering layer (`_generate_row`).
