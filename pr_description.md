💡 **What**
Added an `.empty-state` container for dynamically generated empty filtered tables in the interactive dashboard HTML (generated by `CanaParse.py`). This adds a decorative emoji icon with `aria-hidden="true"`, styled header and helper text to replace the simple, unstyled "No results found" paragraph.

🎯 **Why**
Users previously saw a bare-bones paragraph when no products matched their filters, which felt broken and unfinished compared to the rest of the application's glassmorphism aesthetic. A well-designed empty state provides clear feedback and actionable guidance (e.g., "Try adjusting your search criteria") while visually aligning with the `listing_report.html`'s style.

📸 **Before/After**
*Before:* `<p style="color: var(--text-muted); padding: 1rem;">No results found for this filter.</p>`
*After:* A stylized `div.empty-state` centered block with a decorative "🏜️" icon, an `h2`, and helper text telling users to clear or adjust their filters.

♿ **Accessibility**
Added `aria-hidden="true"` to the decorative emoji (`🏜️`) within the new `.empty-state-icon` element. This prevents screen readers from redundantly announcing "desert" when traversing the empty state, allowing the focus to remain directly on the "No matching items found" heading and subsequent helper text instead.
